# 第六阶段：数据安全、同步与整体验收

日期：2026-10-30。版本：0.6.0。沿用现有 LifeHub Site，无新建站点，无 AI API。

## 交付状态

本阶段源代码、官方构建和本机数据验收完成。遵照用户“未经确认不得正式发布”：仅保存待审版本和推送代码，**不部署、不更新生产数据库、不扩大访问范围**。线上仍运行第五阶段，本阶段的轮询和新备份界面尚未在生产生效。

本轮不是完整的端到端验收通过：浏览器控制工具因本机沙箱目录访问被拒绝而无法启动；手机视口、文件实际落盘、生产登录和真实不同设备的验收尚未完成。

## 1. 已完成的功能

- 保留十类业务模型、所有已有业务模块、首页真实摘要、布局和显示偏好。
- 统一鉴权、同源 JSON 写入、严格字段校验及 2 MB UTF-8 请求限制。读取、导出、预览、恢复均按服务端身份限定所有权。
- 从已认证读取获得账户数据空间标识；每次写入检查该标识。缺少标识要求重载，身份切换拒绝旧请求。该标识不代替身份验证。
- 用户 revision、完整记录与撤销信息在同一个 D1 batch 事务中读取；前台约 15 秒检查版本，重新聚焦/联网时检查，失败按 30 / 60 秒退避。后台暂停；编辑时提示远端变化，保留草稿，关闭弹窗后读取。
- 所有业务记录和首页偏好均要求 UUID operationId。响应丢失时保留原提交 ID 与内容，重试不会重复写入；可核对服务端回执。仅在内存保留结果待确认的请求，关闭/重载页面不保留待确认表单，重载后应核对已保存记录。
- 登录失效或账户变化清除页面记录、弹窗、内存重试内容。旧读取、保存、撤销、导入预览、恢复、导出的迟到响应及错误不能恢复旧账户内容。
- 全部数据、单模块、首页配置导出；服务端导入预览、字段/关联/唯一约束/打卡历史/并发检查、范围确认、事务恢复和重复确认去重。
- 合并默认仅新增：同 ID 同内容不改动，同 ID 内容不同或同范围预算等业务键冲突会阻止导入。替换仅限文件声明范围，须勾选核对再确认。现有打卡与规则历史不能被截断。

## 3. 数据存储方式

Sites 原生工具确认现有线上站点实际绑定 **Cloudflare D1，绑定名 DB**，已有 records、revisions、operations、财务/生活回执及事务守卫表。并非 localStorage 或静态 JSON 冒充数据库。

个人记录和首页偏好同存 D1，owner_id 由服务端 ChatGPT 身份决定，客户端不能指定。记录有 UUID、创建/更新时间、版本。金额存整数最小单位，BigInt 分币种汇总。事务与 revision 守卫保护写入；恢复计划只保存摘要、数量、账户、版本与时间，不存完整备份正文。

新增 0004 迁移仅添加私有备份方案表和索引，已应用本机测试库；生产迁移待用户确认部署时应用。既有迁移保持不变，无用户 seed。

浏览器内存用于显示和暂存未确认请求；localStorage 只供第一阶段旧布局显式迁移。业务记录、新偏好、备份和凭证均不写入浏览器持久化存储、源码或公共资源。业务代码不记录个人正文/金额/身份头。文件响应 private/no-store，同源鉴权 POST，避免搜索和备注出现在 URL 日志中。

## 4. 跨设备同步的真实能力与限制

原生 Sites 检查确认：现有站点是 custom / owner-only，只有 owner，无组授权，无外部访客。Sites 提供真实 ChatGPT 身份和服务端 D1；生产读取需经登录后按 owner 查询。站点访问权限与记录所有权是两层独立检查。

同一私有站点、同一 ChatGPT 账户在不同设备可以访问同一共享 D1。第六阶段代码在部署后提供前台版本轮询；当前线上第五阶段仍按进入页面、聚焦和手动刷新读取。不是 WebSocket 实时推送，没有离线队列或自动合并冲突。

已验证的是**同一台电脑上两个独立客户端通过实际本机 D1 的一致性**，以及模拟两个服务端身份的隔离。没有两台实体设备和生产登录的端到端实测，因此不宣称真实跨设备验收已经通过。官方本机模拟用户 local_seedy 和本机库与云端完全分离，不能用它模拟真正的云端身份或跨设备同步。

并发 409 不静默覆盖；保留草稿供用户参考，关闭表单并读取最新记录，再重新编辑。离线不接收保存；超时不能确定服务端是否已提交，须保留原内容安全重试或刷新核对。

## 5. 备份恢复说明

1. 在“设置与数据备份”选择全部 / 待办日程 / 消费预算 / 学习 / 习惯 / 收藏 / 首页配置，再导出 JSON。导出从服务端读取最新数据，不依赖当前页面缓存。
2. 文件格式 lifehub-backup V3，包含声明范围与记录；兼容 V2 完整备份。每份最多 1000 条，导入请求最多 2 MB UTF-8。过大的导出会提示缩小范围；当前没有大数据量自动分卷。
3. 选择文件或粘贴 JSON，默认合并仅添加新 ID。若有冲突，先核对原因；不要未经核对直接切换替换。
4. 服务端预览展示范围、当前/文件数量、新增/更新/移除/相同数量、冲突及提示。预览不改个人记录。无有效方案不提供执行入口。
5. 替换须核对范围并勾选确认，再点击确认按钮。V2 与 scope=all 影响全部模块及配置；其他 scope 仅影响该范围。现有打卡和规则历史受保护，缺失历史的恢复会拒绝。
6. 预览方案绑定账户、内容摘要和数据 revision，10 分钟内有效。文件变化、账户变化或任意设备写入后须重新预览。恢复在单个 D1 batch 中原子执行，异常整体回滚；同一已执行方案再次确认只返回当前状态，不重放旧内容。
7. 导入成功后 ID 与创建时间保留，替换的更新时间和版本刷新；全部/待办日程替换会使旧撤销快照失效。备份不包含登录凭证、站点权限、用户 owner_id 或操作回执，不会更改站点可见范围。

JSON 是**未加密文件**，可能包含个人消费、笔记等内容，应保存在可信设备或自行加密的存储中。本阶段未实现密码加密备份、自动定时备份、后台持续同步或平台数据库级灾备承诺。
