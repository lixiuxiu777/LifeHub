# 收支与预算规则

V1 第四阶段，2026-10-29。沿用原 LifeHub Site 与私有 D1，未扩展公开访问。

## 金额与账务日期

Expense 同时表示收入和支出，direction 分别为 income / expense；amountMinor 始终为正整数，不能用负数混淆方向。单笔最高 10^12 最小单位。CNY / USD / EUR 精度 2、JPY 精度 0、KWD 精度 3。十进制字符串先转换为 BigInt 再验证范围，拒绝科学计数法、零、负数、额外小数，不静默四舍五入。

汇总使用 BigInt，不进行跨币种相加或隐含换汇。每月收入、支出分别求和，结余 = 收入 − 支出。金额输出保留本币固定精度，负结余与负剩余精确显示。图表坐标和进度条使用比率近似值；金额标签、表格和导出使用精确值。使用率截断到两位小数，进度条封顶 100%，文字保留真实超支比例。

日期为有效 YYYY-MM-DD 账务日期，月份按字符串所属月份确定，不随显示时区转换；新建默认日期按用户显示时区取今天。改变币种不会换汇，需填写该币种的正确金额。

旧消费记录未提供 direction 时按支出读取；未提供支付方式按未指定读取，商家和标签为空。旧预算按总预算读取。每条记录沿用服务端 UUID、创建/更新时间和版本机制。

## 预算与统计范围

每用户、月份、币种可设置一个总预算，同一范围内每个分类可再设置一个分类预算。分类按修剪空白后的字面值精确匹配；不会自动改写历史分类。分类收入不占用分类预算；预算支出不减去收入。

总预算使用当月该币种所有支出；分类预算只使用同名分类支出。剩余 = 预算 − 已支出。分类预算不累加到总预算；分类预算合计大于总预算时提示。没有预算时明确显示未设置，不能将零预算当作默认预算。可以按月份切换查看历史收支和预算。

月份和币种决定摘要、预算与图表范围；明细的搜索、日期、分类、收支类型、支付方式仅影响明细和明细 CSV，不改变整月摘要。日期范围反向时提示并禁止明细导出。明细每页 20 条，导出包含所有匹配记录。分类图仅含支出，六个月趋势分别画收入和支出；没有记录的月份显示真实零值，没有数据时显示空状态。

新增、编辑、删除成功后服务器返回最新记录快照，首页、预算和图表重新计算。删除前确认；财务记录不提供单步撤销，删除前可导出完整备份。请求 operationId 在 D1 事务内保存去重回执，网络重试使用相同编号不会重复记账；同编号不同请求内容被拒绝。版本或事务冲突时刷新核对。

## 导出与隐私

- 明细 CSV：所选月份、币种和当前筛选，包含 ID、日期、收支、币种、精度、金额、分类、支付方式、商家、标签、标题、备注及时间元数据。
- 预算 CSV：所选整月及币种的所有预算，含范围、预算金额、已支出、剩余和使用率。
- 月度 JSON：所选整月及币种的全部收支、预算及统计，不受明细筛选限制。记录的 amountMinor 为安全整数；汇总最小单位为十进制字符串，避免 JSON 数值精度损失。

CSV 使用 UTF-8 BOM、CRLF 和双引号转义。用户文本如以公式符号（含前导空白）开始，添加单引号防止电子表格执行公式；这不会修改数据库记录。精确金额以固定小数文本生成。

月度 JSON 用于分析留存，不是完整恢复备份；恢复请使用设置中的 lifehub-backup V3（兼容 V2）。财务扩展字段包含在完整备份中。恢复时总预算/分类预算唯一约束仍有效，任何冲突整体回滚。恢复不重放历史财务保存请求。

数据按服务端身份过滤，只通过私有 API 读取与导出，不写公共静态资源或日志。不接外部图表、分析服务或 AI。导出搜索条件通过 POST 请求体发送，避免进入 URL 日志；响应 private/no-store。下载文件由用户保管。同步依赖同站点同 ChatGPT 身份和真实 D1；本机开发库不跨设备，生产登录及不同实体设备验收状态见验证记录。
